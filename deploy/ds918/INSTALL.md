# SCREENIT. on a Synology DS918+

Requires Synology Container Manager (or Docker Engine + Compose), a private LAN and a Mac running Docker Desktop. Browser and background alerts use **one** workspace on the NAS. Do not forward this unauthenticated service to the internet.

1. On the Mac, in the **updated** `~/Docker/screenit`, run `sh scripts/build-ds918.sh`. This builds and smoke-tests a private `linux/amd64` image locally (also on Apple Silicon), then exports a Docker image archive in `~/Downloads/screenit-ds918-1.1.8/`. Nothing is pushed to a registry.
2. **Mac workspace:** if `data/screenit.sqlite3` on the NAS is already the complete workspace copied with Screenit stopped, skip the data export and keep that folder. If the NAS `data/` folder is empty, finish any edits on the Mac and close its tab. From the updated source folder run `sh scripts/export-mac-data.sh`. It stops the existing container in `~/Docker/screenit`, copies everything mounted at `/data` (bind mount or Docker volume), checks the SQLite copies and prints the number of alerts and history entries. The original remains on the Mac. If you used a custom build output folder, pass it to this script too. Never merge SQLite files from different copies.
3. In Finder/SMB or File Station open **`/Docker/screenit`** on the NAS. Copy `compose.yaml`, `screenit-amd64.tar` and `SHA256SUMS` from the export into this project folder, alongside `data/`. If you exported the workspace in step 2, copy the **contents** of the exported `data/` into the empty NAS `data/`. Check for `/Docker/screenit/data/screenit.sqlite3` before starting. Import `screenit-amd64.tar` under **Container Manager → Image → Import / Add from file**. In a NAS terminal, from the project's actual filesystem directory, the equivalent is `sha256sum -c SHA256SUMS && sudo docker load -i screenit-amd64.tar`. The Compose mount is relative to the project (`./data:/data`), so no DSM volume number is required.
4. In `compose.yaml`, replace `screenit.example.net` in `SCREENIT_ALLOWED_HOSTS` with the actual reverse proxy hostname (no scheme or port). In DSM, proxy HTTPS on that hostname to `http://127.0.0.1:8080`, preserving the browser's Host header. No `.env`, DSM account creation or Compose `user:` entry is required. The DS918+ build runs as container root (UID/GID 0:0), like TraderJourney. Keep the existing data directory mounted.

5. In Container Manager create a **Project**, select that NAS folder and its existing Compose file, and start the project. Or run `sudo docker compose up -d --no-build` there. Compose uses the imported `screenit:latest` image.
6. Open `https://<your-proxy-hostname>` from the Mac. Check the version, your filters, favorites, alert rules and History. Keep the Mac container stopped to avoid duplicate alerts. To roll back, stop the NAS project first, then `cd ~/Docker/screenit && docker compose start screenit` on the Mac. Allow access only from your trusted LAN/VPN.

For an update, import the next `screenit:latest` archive and recreate the container in the same project, preserving your proxy hostname and `data/`. Stop the service before backing up `data/`. Optional provider keys belong on the server, outside the image and archive.
