# Integration contract — v1

All times UTC epoch milliseconds. Percent means percentage points (`1.5` = 1.5%); funding is percent **per hour**. Unknown/non-finite → null or absent, not 0. JSON camelCase. `catalog()`/`defaults()` in this directory own allowed keys. No imported market feeds or database in this package.

## Python boundaries, importable from repository root

- `src.markets.MarketFeed(data_dir: str)`: called concurrently by HTTP charts and background threads. `refresh(exchange: str) -> snapshot` does one bounded refresh. No global start/run on import. Propagate exchange failure or return non-live status. `candles(exchange: str, symbol: str, interval: str) -> list[candle]` for a known instrument (validate with catalog); time-ordered OHLCV. Quote volumes in quote currency, proxies/coverage documented. No browser dependency. Market-specific SQLite file may be used for bounded time-series history.
- Snapshot: `{exchange, asOf, status, rows, message}` where status = `live|stale|warming|error`; optional message, asOf=last successful observation or null. Row `{symbol, label, at, metrics, trend}`; symbol is exchange-native (e.g. `BTCUSDT`, `BTC`, `xyz:NVDA`); favorites use `exchange:symbol` (split only first colon). `metrics` keyed by catalog ID; emit only fresh usable numbers, use null for insufficient history. `trend` is list of chronological finite prices or null gaps across up to 24h, never synthesize. `at` observation time, not request/cache access time. `candle={t,o,h,l,c,v}`. Incomplete observations must not leak values into alerts. An optional `metricAt` map can give source times per metric (server must honor it).
- `src.server.Store(path: str)` takes a SQLite **file** path (parent exists). `src.server.Service(store, feed, notify_url: str, poll_seconds: float=15)`; `start()` launches background polling/evaluation and delivery; `stop()` stops it. `src.server.make_http(service, host: str, port: int, ui_dir: str)` returns a stdlib HTTP server; caller owns serve_forever/shutdown. System entry point `python3 -m src.app`. A feed can be injected for deterministic offline integration. Public listen port 8080 in container, host publish loopback. Rules may opt in to an HTTP(S) ntfy server and a single topic. Avoid DNS-rebinding/foreign-origin writes and arbitrary static paths; reject invalid/oversized inputs. Bound work and retries. Never send to production during tests.

## Browser HTTP API, same origin

Alongside ticker `quotes`, SSE `windows` messages contain `{windows, fiveReady}`. Each entry is `symbol: [changedMetrics, metricAt]`; a null metric explicitly removes the old value. A window-only event never advances the venue price timestamp. Full snapshots remain authoritative on reconnect. `fiveReady` counts initial 5m coverage, not all longer histories. `capSource` is optional on rows.

For candle history, `GET /api/candles` also accepts `limit` (1–499 for Binance, 1–2881 for Hyperliquid; default 160) and an optional exclusive UTC millisecond `before` cursor. Each page is chronological. An empty page means no older candles were returned for that request.

`GET /api/catalog` returns `catalog()`. `GET /api/health` returns `{ok: true,...}` for service readiness. `GET /api/market?exchange=binance` returns latest full snapshot (empty warming until ready). `GET /api/candles?exchange=binance&symbol=BTCUSDT&interval=15m` returns `{candles:[...]}`. Target symbols from known snapshot only. `GET /api/settings` returns `{revision,settings}`. `PATCH /api/settings` JSON `{revision,changes:{...}}` (partial top-level keys); returns same shape; stale → HTTP 409 with authoritative `{revision,settings}`. UI handles conflicts visibly, never silently discards concurrent same-key changes. Persist *all* user preferences including search, sort, columns, favorites, filters, chartInterval. Only ephemeral interactions (open dialogs, draft invalid values) are not settings.

`GET /api/alerts` → `{rules:[rule]}`. `POST /api/alerts` full rule sans id/revision → 201 `{rule}`. `PUT /api/alerts/<id>` full rule incl revision → `{rule}`; `DELETE /api/alerts/<id>?revision=N` → `{ok:true}`. Conflicts → 409. `GET /api/history` → `{events:[{id,ruleName,exchange,symbol,at,message,delivery}]}` newest first, delivery = `off|pending|sent|failed`. Symbols are strings, rule target null = whole venue. Rule `{id, revision, name, exchange, symbol, enabled, repeat, groups, cooldownMs?, sound?, ntfy?}`. `ntfy` is absent/null when off, or `{server, topic}`. `once` fires once per rule/symbol; `rearm` evaluates again after a per-symbol cooldown (default 300000 ms), without requiring recovery for levels. A crossing in cooldown is not queued for later. `groups` = array of nonempty AND arrays, OR between groups. Condition `{metric, op, value, upper?}` also used for filters; filters AND. `between` and `outside` use lower/upper, inclusive range. First fresh observation can satisfy a *level* rule; *cross* needs consecutive usable values, never across stale/missing/restart gaps. `price` and `changeUsd:*` alert rules require one symbol. Stale/failure for an entire venue must also break crossing continuity. Repeated delivery of the same observation is not a new trigger. All error responses JSON `{error:human readable}` except conflicts as specified. For strict same-origin request protection compare Origin when supplied, validate Host loopback or explicitly allowed host; JSON-only mutations. Notifications configuration is server-only, optional env `SCREENIT_NTFY_TOKEN`, no secret logging.

Static entry `src/ui/index.html` and relative ESM/CSS files, served at `/`. All product text is English. No external frontend fonts, packages, trackers or Orion integration. The same-origin `GET /api/market/stream?exchange=…` sends an initial `snapshot`, then `quotes` deltas (`symbol → [source time, metric values]`) or a new snapshot on resync. Reconnects always receive a full snapshot. Regular HTTP snapshots remain the fallback. No settings Save button; alerts may have explicit create/delete actions. Provider-specific missing values render `—` and explain coverage.
